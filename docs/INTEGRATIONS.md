# Signed release integrations

All five catalog apps use the same GitHub-hosted signing and automatic publishing process: [Daybreak](https://github.com/jeethsuresh/weather/blob/main/ANDROID_RELEASES.md), [Spacetime](https://github.com/jeethsuresh/spacetime/blob/main/ANDROID_RELEASES.md), [River](https://github.com/jeethsuresh/river/blob/main/ANDROID_RELEASES.md), [Glyph](https://github.com/jeethsuresh/launcher/blob/main/ANDROID_RELEASES.md), and [Bazaar](../ANDROID_RELEASES.md).

Increase both the version name and Android version code and update `changelog.json` in the same PR, then merge or push to `main`. The **Signed Android release** workflow validates the changelog and tests before loading the original signing key, verifies the permanent certificate, package, version and minimum Android version, and uploads the APK, changelog, checksums and release manifest. It verifies GitHub's uploaded asset digests before publishing automatically. The store receives new releases through its existing webhook or periodic ingestion.

Each new release must publish a `changelog.json` asset with exactly `schemaVersion: 1`, `version` matching the APK version name, integer `versionCode` matching the APK, and a `changes` array of 1–50 nonempty, user-facing plain-text strings. Each entry is at most 2000 UTF-8 bytes; the entire JSON file is at most 32000 UTF-8 bytes. Store ingestion checks the asset size and GitHub digest, parses this schema, and checks its version against the verified APK before accepting the release. Its entries become the existing `notes` field shown in Android's Release notes dialog and the web app's What's new section. A malformed or mismatched JSON asset blocks ingestion; a legacy release without it retains the GitHub release body as notes.

Every repository uses a main-only `android-release` environment containing `RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, and `RELEASE_KEY_PASSWORD`. Private keys and passwords are encrypted secrets, never Git files or release assets. Preserve the original protected backup and existing certificate when maintaining them.

For a verification-only build of an already published version, run the workflow manually on `main` with `publish_release` disabled. It saves a verified signed artifact for 14 days. Existing releases, tags and assets are never overwritten.

Glyph uses the Android package `cool.gravitas.glyph` starting with 0.6.2 and keeps its original signing certificate, SHA-256 `508184332d54eadbf5ad558c0b00c8350769cb386130c68eeec4aa8bf47c8b09`. Users install Glyph alongside the previous `app.still.launcher` package and set up their home screen and keyboard again. Published APKs use `StillLauncher-{tag}-android.apk`. Publish and verify the new Glyph APK before deploying the Store catalog change so the listing can immediately ingest the new package.
